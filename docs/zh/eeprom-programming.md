# Candis EEPROM 读写与生产配置

[使用文档](README.md) · [English](../en/eeprom-programming.md)

本流程面向独立编程夹具和获准的产线维护工位。镜像字段、ID 和 CRC 以 [Candis EEPROM V1](eeprom-v1.md) 为准。设备固件按 [启动枚举](expansion.md#冷启动枚举) 读取描述符，正常运行不写 EEPROM。

## AT24C02 事务

Dock v1.2 与 Gamepad 的 U10 使用英锐芯 AT24C02 SOP-8（`C688857`）。其容量为 256 字节（32 页），字地址 8 位，页长 8 字节，内部写周期最大 5 ms。产线应按实际料号、温度和供电条件验收。替代器件需复核页长、地址脚、WP、时序和工作电压。 [英锐芯 AT24C02，§2、§10–13](https://atta.szlcsc.com/upload/public/pdf/source/20200619/C688857_168265888F77B455D6D4136881F4BB15.pdf)

- **器件地址。** 绑带在断电时设置，A2/A1/A0 固定于本器件 VCC 或 GND。7 位地址为 `0x50 | (A2<<2) | (A1<<1) | A0`，传给 I²C 驱动。BTB `0x50`、LEFT `0x51`、RIGHT `0x52` 的线上写/读控制字节依次为 `A0/A1`、`A2/A3`、`A4/A5`（十六进制）。地址来源和模块绑带验收见 [位置与地址](expansion.md#位置与地址)。
- **随机起点顺序读。** 以 100 kHz 发送 START、器件地址加 W、1 字节存储偏移，再发 repeated START 和器件地址加 R。主机每收到一字节发 ACK，最后一字节发 NACK，随后 STOP。读取起点 `0x00`，固件取 134 字节，编程和备份可取全 256 字节。不允许读出范围超出 `0xFF` 后回绕。地址阶段的 W 仅用于设置偏移。
- **页写。** 发送 START、器件地址加 W、1 字节存储偏移和页内数据，然后 STOP 启动内部写周期。每笔数据长度为 `min(剩余字节数, 8 - (offset % 8))`，限同一页。跨页发送会回绕覆盖本页数据。逐页比较原数据与目标，跳过一致页。每个待写页可在首尾差异之间写一个连续区段，区段内其他字节使用原值。
- **ACK Polling。** STOP 后按同一 7 位地址发 START 和写地址，结束该次探测。收到 NACK 时等待短间隔重试（例如 1 ms），收到 ACK 后回读并比对刚写入的字节。工位以该次 STOP 为起点设置 30 ms 上界，超时、总线故障或读回不符均中止。工具只支持组合读时，先等待实际满 5 ms，再用有界的同页回读确认就绪和内容。ACK 表示可继续事务，字节回读才确认编程。
- **WP。** 7 脚接 VCC 保护整个存储区，只允许读取。接 GND 允许写入。Dock v1.2 与 Gamepad 的 WP 硬接地，由运行固件和工位流程限制写权限；外部工位不得对硬接地的 WP 强拉高。新模块应设计默认上拉到本器件 VCC 的 WP，并提供授权夹具可控的低电平写入通路。配置 WP 前核对器件电平域，编程结束恢复保护并回读。

## 首次烧录与批量放行

```text
确认模块电气与产品配置 → 登记 Vendor ID / Product ID / Revision
  → 生成 V1 字节序列 → 计算三段 CRC → 审核产线镜像
  → 单目标写入 AT24C02 → 回读与独立解析
  → 冷启动识别 → 对照固件配置验证驱动和资源
```

1. **生成工单和镜像。** 固定产品登记版本、BOM/读写工装、位置、7 位地址与装配修订。给目标单板分配唯一序列号，填写日期、批次、工厂及已获准的参数。依偏移编码、补零，覆盖三段范围计算 CRC。将描述符置于镜像开头，余下 122 字节填 `FF`，得到 256 字节文件。独立解码确认长度、字段、TLV、CRC、目标产品和限制，记录镜像 SHA-256。参数来自审核或标定记录。
2. **核对目标并备份。** 夹具一次只连接一个实体器件或一道隔离后的支路，确认板号、位置、Pin 1、A2/A1/A0、WP、电压和接地。编程器独占 I²C，此时应用、UART0 外接驱动和其他同地址目标均释放或隔离。在板编程另外确认 Q3、DC1SW、全域负载和反向供电边界。读取全 256 字节归档。仅全 256 字节均为 `FF` 的器件可走首次写入。其他内容或未识别的装配须匹配返修工单。用工位上的实体标识确认工件。
3. **分阶段写入。** 若回读的 134 字节已与目标完全一致，跳过写入并走最终校验。否则先将 `0x00..0x02` 写成全零，回读确认 Magic 失效。暂留 `0x03..0x07`。按页比较并写入 `0x08..0x85` 中需要更新的区段，每笔执行 ACK Polling 和回读；`0x80` 页最多写描述符的前 6 字节，避免覆盖 `0x86..0x87`。再次比对整个 `0x08..0x85` 成功后，用一次页写提交目标 `0x00..0x07`。
4. **回读放行。** 恢复支持的 WP 写保护，读取全 256 字节并检查前 134 字节逐字节匹配、保留区符合预期、三个 CRC 和字段均通过。新空白器件预期保留区为 `FF`，在役维护比对备份区。另行断电冷启动复测，记录主机选择的身份、槽位、电源及驱动配置。批量工位保存本工件的板号/序列号、地址、绑带、镜像及回读哈希、工位和测试结果。任一不符时隔离该工件，不记为通过。

生产须确认使用的固件支持 `CND`。现有 `ESP` 版底板可继续从兼容入口识别。迁移为 `CND` 前先归档原镜像，再根据登记和工单生成完整新镜像，逐项检查字段语义及 TLV。[ESP-Mosaico 烧录示例](https://github.com/esp-mosaico/esp-mosaico-bsp/tree/5674ab1f4cc250350d02e0f03c409b1877c954ca/examples/module_eeprom_programmer)

## 参数修改与恢复

- **校准返修。** 全量读取、备份并校验原镜像。将获准更改的 TLV 合并到原参数集，保留其他字段和未知可选 Tag。重新生成 Parameter Length、补零及 Parameter CRC。先比较完整目标镜像，再按分阶段写入流程提交；Identity 与 Manufacturing CRC 在原字段不变时保持原值。普通使用偏好在 Host 配置维护。
- **写入中断。** 将工件标为待复验。电源稳定后独占目标并重读 256 字节，根据工单选择恢复原备份或完成已审核的新镜像。写前比较，写后全量比对、解析并复验冷启动。Magic 失效、CRC 失败或读回错时，设备固件保留诊断并停用对应驱动。现场不自动补写。
- **备份与寿命。** 两份 134 字节描述符需要 268 字节，单颗 AT24C02 采用单槽和外部备份。提交首页放在最后可降低断电时加载未写完镜像的概率，量产仍需停电故障试验和复验。工单存储镜像、全量回读、哈希和版本对应关系。启动、轮询、故障计数和普通配置变化均不写 EEPROM。重复输入及已一致页面跳过写入，返修有界重试并统计异常。对断电或无原备份工件从可追溯的登记重新生成，身份无法核对时维持隔离状态。
