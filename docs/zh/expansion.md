# Candis 扩展识别与资源管理

[使用文档](README.md) · [English](../en/expansion.md)

Candis 核心板的 30Pin CN1 和 50Pin CN2 同时连接一块 Dock BTB 底板。BSP 识别 Dock v1.1/v1.2 为 `CANDIS_BASEBOARD_BB`（EEPROM 产品 ID 2）。EEPROM V1 格式保持不变，格式有效但不属于受支持 Dock 修订的产品身份返回 `ESP_ERR_NOT_SUPPORTED`。只有已批准的 Dock 配置继续枚举两个 20Pin 子槽。

```text
Candis 核心板
  CN1 + CN2 → BTB 0x50 → 一块底板
                         └ candis_dock
                           ├ LEFT  (U6) → 0x51
                           └ RIGHT (U7) → 0x52
```

## EEPROM 接线

Dock v1.2 的 U10 为英锐芯 AT24C02，立创料号 `C688857`。U10 的 1/2/3 脚 A0/A1/A2、4 脚 GND 和 7 脚 WP 接地，7 位地址为 `0x50`。8 脚 VCC 接 `TG28_DC1SW`。5/6 脚分别为 `EEPROM_SDA`、`EEPROM_SCL`，经 Q3（2N7002DW）接 `EXP_SDA`、`EXP_SCL`。Q3 两个栅极和 R21/R22 两个 4.7 kΩ 上拉均接 DC1SW。Dock 的 U6/U7 共接 Q3 的 `EXP_*` 侧。核心板本身没有底板描述符器件。

## 位置与地址

| 位置 | 7 位地址 | A2/A1/A0 | 依据 |
| --- | --- | --- | --- |
| BTB U10 | `0x50` | `000` | Dock v1.2 网表确认 |
| Dock LEFT（U6） | `0x51` | `001` | 本规范约定，由模块或转接板接线落实 |
| Dock RIGHT（U7） | `0x52` | `010` | 本规范约定，由模块或转接板接线落实 |

LEFT/RIGHT 的 A0/A1/A2、WP、VCC 是否符合约定，须用各模块或转接板的原理图和实物验证。已核查的 Dock 没有送到接插件的地址选择信号。模块的地址绑带在断电时设置，地址脚按目标位置绑至模块 EEPROM 的 VCC 或 GND。生产夹具一次只接一个位置，核对实物位号、供电脚、A0/A1/A2 和 EEPROM 实际响应，再核对双槽组合。量产装配使用经过验证的方向防错或专用转接板，两座的相同排针外形允许误插。

同型号可以复用同一 `Vendor/Type/Product/Revision/Variant` 和驱动代码。为每个获准插槽登记电气和资源映射。地址绑带随安装位置设置，序列号随模块走，驱动实例按槽位及代次分配。两槽的电源、I²C 和通用引脚针位都不同，通用模块需用匹配的转接或走线。摇杆参考模块当前只定义在 LEFT。若一个地址绑错，固件从 ACK 或描述符看不出其实际插座。对需要启用驱动的组合，板级配置须有装配证据或可验证的防错方式。

同一总线两个器件占同地址时，ACK 可能仍然正常，读出的数据可能不稳定，也可能一致且通过 CRC。连续一致读回只是诊断。子模块误绑到 `0x50` 也会影响父板的读取。发现冲突、疑似串读或不符合装配记录时禁止激活受影响的总线和模块，报告位置、地址及错误。排查时断电后分件接入或用隔离工位核对绑带。固件不尝试改写地址、用 GPIO 推挽压制同地址设备，或将其中一个设备当成优先响应者。

## 冷启动枚举

1. **保持核心功能可启动。** 固定核心资源照常初始化，扩展专用线保持高阻且暂不启用相冲突的复用功能。仅在已确认 BTB 装配和探测供电条件的核心板配置上开启自动识别。DC1SW 预供电会同时给 TF、IMU、U10 和接入的子模块供电，准入前要求这些负载上电默认安全且总负载已验证。其余情形保留仅核心板模式，记录探测未启动的原因。
2. **接管扩展 I²C。** 主 I²C0 使用 GPIO6/7。扩展用 GPIO Matrix 将 I²C1 接到 GPIO58 SCL 和 GPIO59 SDA。这两脚原生功能为 UART0 TX 和 RX。确保 UART0 与外接夹具释放引脚，保留已验证的下载/诊断路径，现场可用原生 USB OTG CDC。用开漏模式和唯一总线所有者接管，保持扩展动作与应用、诊断和写入工位互斥。检查 DC1SW 初态、上游电源及稳定时间，确认 SCL/SDA 空闲为高，才开始 100 kHz 读取。
3. **发现 BTB。** 只访问 `0x50`，从 `0x00` 读取 134 字节。每地址最多三轮，轮间建议至少 5 ms。单次探测超时 30 ms，组合读超时 40 ms。在有响应时要求两次连续读回相同内容，再执行 [V1 校验](eeprom-v1.md#校验与兼容)。稳定 NACK 记为无响应。内容不一致，或 ACK、NACK 与超时混杂时，记为不稳定。SCL/SDA 卡低或总线级错误时中止此总线枚举。
4. **确认父配置后发现子槽。** `0x50` 命中已验证的 Dock 版本及装配配置时，依次用同样规则读取 `0x51`、`0x52`。这一步完成前所有插槽功能驱动保持停止。只扫描注册地址，无底板、未知底板或独立 BB 不进行子槽探测。两个子槽的地址和身份都纳入同一轮资源审核。
5. **申请资源，再初始化。** 将整个拓扑与当前核心功能合并审核。记录位置（BTB/LEFT/RIGHT）、I²C 控制器与 7 位地址、解码身份、序列号、状态和生命周期代次。设备句柄绑定当前代次。先一次性预留所有资源，再按配置的上电/复位次序启动并提交实例。申请或初始化失败时回滚已取得的资源，核心功能继续运行。

| 结果 | 默认动作 |
| --- | --- |
| 探测门禁关闭、DC1SW 不稳、UART0 未释放 | 仅核心板模式，报告原因 |
| `0x50` 无响应 | 仅核心板模式。无底板、未焊 EEPROM、掉电或断线均可能表现为 NACK |
| ACK 后全 `FF` 或全 `00` | 记录器件响应及空描述符，保持未绑定 |
| 短读、CRC/格式失败、两次内容不一致 | 记录错误与地址，保持未绑定 |
| 未知厂商、产品、版本、修订、变体、错误位置或重复序列号 | 保留诊断信息，禁止受影响实例。重复序列号检查同厂商同产品的非零序列号 |
| 子槽无响应或不兼容 | 该槽无绑定。只有已验证装配能证明其他功能不受它的物理负载影响时，才允许其他功能启用 |
| 检出总线碰撞、卡低或异常负载 | 停止受影响域上的探测与驱动，安全释放本管理器持有的资源，诊断后冷启动 |

发现阶段退出时，撤销临时 I²C 设备和总线句柄，再释放探测持有的引脚和电源引用。未知装配保留仅核心板模式。无 EEPROM 的已知底板可由操作员核对实物、板号和电源后显式选择固定装配配置。正常自动识别遇到无响应保持仅核心板模式，历史缓存、产品名、ACK 和试探驱动都不作代替。TF 卡检测也需要确认 U6 空置或该模块在 GPIO39 上始终满足共享条件，单次 NACK 不能证明空槽。

## 资源申请

发布配置按核心板修订、父底板修订、槽位和 [产品键](eeprom-v1.md#id-与硬件修订) 查表。登记每个功能的 GPIO 方向、上电状态、上下拉、复用、可共用条件、引脚电压域、总线控制器和设备地址、供电依赖、电流及停机顺序。驱动注册表显式提供初始化与释放方法。EEPROM 的功能参数只有在对应驱动绑定后才使用。

| 资源类别 | 申请和冲突规则 |
| --- | --- |
| GPIO 与复用 | GPIO35 跨槽共享，GPIO39 还连接 TF 卡检测，GPIO37 与核心板 LED 共用。输出及复用默认独占。只读共享需要同电平域、相容上下拉、无另外的输出驱动且信号语义一致。优先保留核心、启动/复位、恢复、板内已接负载；GPIO33/34 USB Serial/JTAG、GPIO54–57 外部 JTAG 用途须先确认。VBAT、PWRON、NTC、VSYS、5V、扬声器差分端和 CHIP_PU 属于固定网络 |
| ADC | 按已验证的 GPIO、ADC 单元/通道及单端或差分模式申请，独立记录衰减、量程和标定。ADC 引脚不能同时作数字输出或被另一个实例用不同模式配置 |
| I²C | 总线按控制器和引脚共享，设备按 `(总线, 7 位地址)` 独占。扩展总线预留 `0x50..0x52` 给描述符。检查所有已供电设备的地址、开漏、电平、并联上拉及总线电容。主 I²C 上的 BMI270 为 `0x68`，与扩展 EEPROM 分属两个控制器 |
| SPI | 明确独占的控制器或已审核的共享 SCK/数据线、独立 CS 与最大时钟。非选中设备须释放返回数据线。核心 Flash、PSRAM 和屏已占用的资源先锁定；Dock 两端暂未登记通用 SPI 针位 |
| UART | 申请控制器、TX/RX 与方向控制并核对连接对端。GPIO58/59 处于扩展模式时禁止 UART0 使用该管脚对，空闲归还前确认电源与线路状态。Dock 两端暂未登记通用 UART 针位 |
| 电源 | DC1SW 和其他共用轨用引用管理并锁定配置。按 TG28-ESP v1.0 表 6-3 的 DC1SW **300 mA** 规格建立预算（默认 OFF），纳入 U10、TF、BMI270 和两子槽的同时稳态、启动浪涌及裕量。其他轨按各自额定、负载及电平验证。一个持有者不能关断其他已生效的引用 |

| 配置 | 固定用法和限制 |
| --- | --- |
| 核心板 | 主 I²C0 接 TG28、RTC、触摸、音频等，显示、存储和下载路径按核心配置保留。无可用底板时扩展专用外设不开启 |
| `candis_bb` | 预留无子槽直连。身份 I²C 为 `0x50`，其余资源随独立板图/BOM 登记。不存在从 Dock 继承的默认引脚 |
| `candis_dock` v1.2 | 同一 SDMMC 和 GPIO39 CD，BMI270 经 Q2 接主 I²C0。CN3 为 RSPK 差分端；旧 v1.1 配置的 CN3 为 LSPK，按硬件修订选择声道。U6/U7 只能使用各自经核验的引脚和已验证的共享方式 |
| 摇杆参考模块 | LEFT 的 U6.20/GPIO42、U6.18/GPIO43 为 X/Y，U6.6/GPIO36 为按压输入，U6.11/DC1SW 与 GND 供模块，U6.17/15 为 SCL/SDA。除 EEPROM `0x51` 外无功能 I²C 设备。输入范围、上下拉、防错和实际 ADC 位宽/衰减需验证 |
| 传感器参考模块 | RIGHT 的 U7.16/18 为 SCL/SDA，U7.10/20 为 DC1SW/GND。EEPROM `0x52`，功能 I²C 地址示例 `0x44`，无 GPIO 中断。批准配置须登记实际传感器、地址绑带、总线时序和负载 |

两槽同时启用的前提是地址、电平、资源和电源预算均通过。参考摇杆在 LEFT、参考传感器在 RIGHT 可以形成待验证的并行配置。将 GPIO39 用作自身功能的模块与带卡检测的 TF 配置互斥。共同占用 GPIO35 的两个驱动默认互斥。即便两个同型号 I²C 模块用了不同 EEPROM 地址，功能器件也必须有不同地址或经硬件隔离。

资源裁决先保留核心、启动安全以及已验证的底板固定用途。申请冲突时，只有经验证另外一个设备停用且电气静默的组合，才允许由应用按配置选择优先功能。物理冲突不能靠先启动某一侧解决，两侧均保持未绑定或停止受影响资源。退出时按驱动次序撤销活动，以当前代次为准释放申请，防止迟到回调操作已释放的引脚和总线。

## 生命周期

当前硬件使用**冷插拔和启动发现**。插拔前结束驱动会话并断开 USB、电池及外部供电，等待需要断电的域放电。软件可在同一装配内停机重读身份。运行时检测读错、意外 NACK 或其他故障可以触发停用与诊断，V1 不在带电期间自动换绑实例。驱动释放时先拒绝新请求，完成存储同步和卸载。完成或取消在途事务及 DMA，关闭中断和功能输出并等待回调退出，然后撤销设备、引脚和电源引用。恢复 UART0 前检查扩展 I²C 和所有仍接入的外部驱动已释放。

后续考虑带电插拔时，需要独立槽检测和消抖、受控开关与限流、可隔离的 I²C 和共享 GPIO、上电复位及连接器接触顺序设计。启用运行时换绑前，需验证插拔和负载故障下的驱动停止、释放、重扫及恢复。 [ESP-Mosaico 模块管理器](https://github.com/esp-mosaico/esp-mosaico-bsp/tree/5674ab1f4cc250350d02e0f03c409b1877c954ca/components/mosaico_module_mgr)

## BSP 支持

- `candis_baseboard_probe()` 显式读取 `0x50` 上已部署的 `ESP` 描述符，匹配受支持的 Dock 修订。`candis_baseboard_probe_state()` 和 `candis_dock_get_state()` 可区分已识别但尚未打开的 Dock 和已建立的活动会话。何时探测及使用哪个驱动由应用决定。
- `candis_dock_probe_modules()` 返回 `0x51`、`0x52` 的地址响应。本文规定的 `CND` 解析、子槽描述符校验和整套拓扑的资源分配需完成 Host 集成后使用。
- 部署前，在实际装配上核对连接器方向与通断、硬件修订、地址绑带与 WP、供电时序与组合负载，以及空白或不兼容描述符的启动处理。按预期组合验证模块共用引脚和资源释放。
